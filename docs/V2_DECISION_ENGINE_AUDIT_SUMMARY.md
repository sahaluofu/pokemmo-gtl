# GTL v2 决策引擎审计摘要

**审计建议退回 v2 实施方案。** 先核实收费和改价机制，修正回款假设与候选生成，再用现有库存验证真实交易流水。

原审计基线为 `4c52753`，371 项测试全部通过。实盘库有 0 次快照、0 根 K 线、0 条手工报价。LGBM 的 **+11.57%（343 笔）** 来自模拟数据，生成器预设卖压峰值比价格峰值早一天。该成绩只用于检验模型能否学到模拟规律，实盘表现仍待验证。

## 最先修复的三个问题

1. **上架费的计费单位会让盈亏翻转。** 买入 99 件、每件 9,600，再以每件 10,000 卖出，不重挂时毛利为 39,600。仓库按槽计费 25,000，净赚 **14,600**。按 2018 年官方公告的逐件口径，总费 49,500，净亏 **9,900**。先用同品同价的 1 件和 99 件预览核实现行收费，再核对最低费、封顶、不可堆叠物品及原单改价费用。按核实后的离散费率计算保本价。
2. **卖盘报价不能直接记作回款。** 原回测按未来卖方报价把整笔库存变成现金，并立即用于下一笔交易。买入应按拟买量逐档计价并计入手工延迟。纸面评估须注明成交假设，保留部分售出与未售情景，并避免多张纸单重复占用同一流量。实际回款以本人流水为准。
3. **今天的候选依赖未来有报价。** 原回测先删去缺少未来标签的行，再生成交易。候选只使用决策当时可得的信息。缺少退出报价的仓位仍记入账本，保留库存与资金占用。验收时删掉未来行情，检查当天候选是否一致。

## 盘口与数据流水线

| 问题 | 修正与验收 |
| --- | --- |
| 公开快照无法区分售罄和撤单 | 记录同 ID 减量、整单消失量、可见低价库存和价墙持续帧数。跨帧只报告观测到的降价次数，库存天数注明分母假设与实际覆盖时长。用本人订单分别计算 48 小时售出件数占比和整单售罄比例。 |
| 空盘丢失，旧报价仍会触发新信号 | 区分有货、完整采集但空盘、采集缺失。空盘记库存为 0、价格为空，流量独立汇总。告警注明行情时间和有效期。 |
| 清理原始数据后重放会改写历史 | 写入差分前校验当前帧和前一帧的留存状态，区分真空盘与已清理数据。需要回算生命周期时，保留挂单 ID 事件或归档原始帧。 |
| RP 价格单位混用，上游特征会被未来数据改写 | 将 RP 券报价统一折算为金币/RP，按报价时效过滤。只使用当时可得的有效上游权重，完整配方缺项时标为未知。 |
| 分页采集的报价可能被提前使用 | 记录采集起止时间，从完整快照提交后开始使用该轮数据。 |

## 实施顺序与验收

| 阶段 | 交付与验收 |
| --- | --- |
| **0. 核实市场规则，修正基线** | 用客户端预览和收据核对上架、直接改价、部分售后改价的费用。修复未来筛选、空盘、清理后重放及 RP 和上游特征问题。逐笔核对费用，验证候选只依赖当时信息，重跑后历史差分保持一致。 |
| **1. 管理现有库存** | 先做一份本人账本和一张观察列表。记录成本、已付费、剩余件数、部分回款、改价、撤单和到期。展示低于本人挂价的可见数量、报价年龄及到期提醒。验收时对齐现金、库存和槽位。 |
| **2. 前瞻验证 B 流动性冲击** | 从少量熟悉、已核实堆叠规则的商品开始，只发告警。冻结触发条件和亏损预算，记录人工延迟、实际可买量、拒绝或错过原因和全部尾仓。A 活动周期与 C 平价、成本及礼袋价值先做观察。 |
| **3. 按实际瓶颈加入模型** | 若挂价等待是主要损失，用本人订单估计分档成交率。资金和槽位长期同时用满时，再优化分配。ML 只有在冻结的样本外带来额外净金币时才接入排序。 |

高频做市剧本 D、五页看板和复杂组合优化移出首版。三重障碍、Meta-Labeling 和成交概率模型等到取得可核对的本人订单结果后再评估。

## 收益与准入标准

- 账本按实际买入起算资金占用，随剩余库存成本递减。槽位从上架记到售罄、撤单或到期。用总净损益分别除以总资金日和总槽位日，另列可用现金、未售件数和估值区间。
- 删除“14 天＋30 笔闭环纸单＋58% 胜率”的准入线。即使 30 笔真实交易彼此独立，18 胜的 95% Wilson 区间也约为 42%–75%。评估须计入所有告警、人工拒绝或错过、实际下单及成熟后仍未售的仓位。
- 在相同现金、槽位和人工时段下，与持币及冻结的简单规则比较。按日期或活动分块报告扣费增益、尾仓损失和不确定性。仅在独立时段、保守尾仓估值下仍有增益时，按验证过的容量扩量。
